# Контекст для нового компьютера или AI-ассистента

## Назначение

AI Usage Telemetry Platform — учебный portfolio-проект. Публичный репозиторий: https://github.com/Kir2486/ai-usage-telemetry. Основной чат — чат Codex, в котором проект начат; для продолжения в другом чате достаточно файлов репозитория.

Пользователь готовится к международным Senior Data Engineer позициям, особенно к AI integrations и observability. По предоставленному контексту у него 7+ лет опыта и знакомство с Python, SQL, Spark, Airflow, Kafka и ClickHouse. Это исходные сведения, а не результат нашей проверки навыков.

## Предпочтения обучения

- Просто, тактично и уважительно; короткие ответы, одна тема за раз.
- Объяснять смысл, место в системе и конкретный пример.
- «Дальше» означает следующий небольшой шаг. Если есть вопрос — разобрать его, затем вернуться на основной трек.
- Пользователь должен понимать и писать учебную логику самостоятельно. Ассистент может готовить mock, тесты, окружение и документацию; готовое учебное решение — по прямому запросу.
- Добавлять короткие профессиональные фразы на английском B1–B2.
- Практические кейсы должны быть воспроизводимыми; учебные симуляции так и обозначаем.
- В репозитории нужны подробные комментарии, готовые примеры для чтения, тесты и эксперименты. Пользователь явно запросил расширение учебных материалов; задания остаются отдельно от демонстраций.

## Принятые решения

- Один основной репозиторий; работаем локально, синхронизируем через GitHub.
- Первый MVP: mock API -> Python client -> validated usage events -> JSONL.
- Далее: OpenTelemetry, raw storage, ClickHouse, Airflow/dbt, data quality, dashboards, AI tool integrations.
- Учёт расходов ведётся по полным usage events; sampled traces не считаются полным журналом начислений.
- JSONL — промежуточный учебный формат; гарантии durable ingestion ещё не реализованы.
- Начинаем без расходов на LLM, с синтетическими данными.
- Полные описания вакансий Itexus и Janea Systems пока не получены; требования конкретных работодателей не считаются проверенными.

## Как продолжить

Сначала прочитать AGENTS.md, затем docs/PROGRESS.md и docs/DEVELOPMENT.md. Проверить git status и текущую ветку. Не повторять весь курс: взять следующий шаг из прогресса и сверить его с реальным кодом.

Текущий статус, подтверждённые проверки и незавершённые задания находятся только в PROGRESS.md, чтобы не дублировать изменчивые сведения.
